  Boundary 4: Tool Validator → Student Record Tool
    Input:  Matches GetStudentStatusRequest schema

3. HOW IT WORKS
---------------
The architecture follows a layered security model:

  Student → REST API → Auth → Session → Orchestrator → Tools/RAG → Response

Key architectural invariants enforced:
  a) The AI (LLM) NEVER has direct database access. All data retrieval goes 
     through deterministic tool functions with validated schemas.
  b) No ticket is ever persisted without passing through the Human-in-the-Loop 
     confirmation gate.
  c) The execution loop is bounded to MAX_ITERATIONS = 5 to prevent infinite 
     token consumption.
  d) All tool calls are schema-validated before execution and RBAC-checked 
     to ensure the authenticated student can only access their own records.
